Databases compared

Relational and non-relational database services in Google Cloud, AWS and Azure side by side: managed engines, cloud-native and distributed SQL, NoSQL by data model, and recent changes.

Each cloud offers the same families of databases: managed versions of the familiar relational engines, its own cloud-native relational service built for scale, and a set of non-relational (NoSQL) services for documents, key-value data, caching, graphs and time series. The names rarely line up, so this page maps them side by side, first relational, then non-relational.

Relational: cloud-native and distributed

Each provider has rebuilt the relational database around its own storage layer, separating compute from storage so it can scale reads, recover faster and fail over in seconds. And each has a database that keeps SQL and transactions while spreading data across regions.

Choosing a database

  • Moving an existing database: start with the same engine, managed (Cloud SQL, RDS, Azure Database / Azure SQL). It's the least change and the easiest rollback.
  • PostgreSQL or MySQL that needs more: AlloyDB, Aurora, or (for SQL Server) Azure SQL Hyperscale. Same drivers, more scale and faster failover.
  • Global, always-on transactions: Spanner or Aurora DSQL. Expect to adapt schema and transactions; the payoff is multi-region writes without building replication yourself.
  • New app with simple, high-volume access patterns: Firestore, DynamoDB or Cosmos DB. Model the data around how it's read, not as normalised tables.
  • Caching: Memorystore, ElastiCache or Azure Managed Redis in front of any of the above; MemoryDB if the cache must also be the durable store.
  • Analytics: keep it out of the transactional database. BigQuery, Redshift and Fabric each have zero-ETL or federated links to their cloud's operational databases.

Whatever you choose, the operational baseline is the same in all three: private connectivity only, automated backups with point-in-time recovery, high availability across zones for production, encryption with customer-managed keys where required, and the backups covered by your backup checks (Google Cloud, AWS, Azure).

Compared as of October 2026. Service names, tiers and retirement dates change; check the provider's documentation before deciding.
