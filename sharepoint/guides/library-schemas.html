Library schemas and content type IDs

Content type IDs from 0x down, list templates, schema.xml, and building custom libraries the right way.

Every list and library in SharePoint is defined by a list template (what kind of list it is) and a set of content types (what kinds of items it holds). Content type IDs, the long values starting with 0x, encode the whole inheritance chain. Once you can read them, a lot of SharePoint's behaviour makes sense.

Content type IDs: reading the 0x

A content type ID is a hexadecimal string that contains its parent's ID. Reading from the left, you can see every ancestor:

0x                      System (the root of everything)
0x01                    Item
0x0101                  Document          (Item + 01)
0x010101                Form              (Document + 01)
0x0120                  Folder            (Item + 20)
0x0120D520              Document Set      (Folder + D520)

So a content type whose ID starts with 0x0101 is a kind of Document, and anything starting with 0x0120 is a kind of Folder.

Building your own IDs

There are two ways to extend an ID:

  1. Parent ID + two hex digits (not 00), for example 0x0101 + 01 = 0x010101. Microsoft uses this for built-in types, so avoid it for your own.
  2. Parent ID + 00 + a GUID without dashes. This is the right way for custom content types, because the GUID guarantees uniqueness:

0x0101 00 A1B2C3D4E5F6478890ABCDEF12345678 = 0x010100A1B2C3D4E5F6478890ABCDEF12345678 "Contract", based on Document

A child of that type then adds two digits: 0x010100A1B2C3D4E5F6478890ABCDEF1234567801 for "Supplier contract".

Content type IDs can be up to 1,024 characters long, so deep hierarchies are possible. In practice, keep them to two or three levels.

When a content type is added to a list, SharePoint creates a list content type as a child of the site content type, so its ID in the list is longer than the site version. That's normal: code should compare with "starts with" rather than "equals".

Inside a library definition (schema.xml)

On SharePoint Server, the out-of-the-box document library is defined in the hive under TEMPLATE\FEATURES\DocumentLibrary\DocLib\schema.xml. A list definition has four main parts:

  • <ContentTypes>: which content types the library starts with (for a document library, Document 0x0101 and Folder 0x0120).
  • <Fields>: columns defined only for this list.
  • <Views>: the views, written in CAML.
  • <Forms>: the display, edit and new forms.

The feature's elements.xml registers the template with a <ListTemplate> element that gives it a Type (the BaseTemplate number), a BaseType, a name and an icon.

Don't edit the built-in schema.xml files. Changes are overwritten by updates and make upgrades fail.

Custom library templates: four approaches

1. Save as template (.stp). List settings > Save list as template stores the library (optionally with content) in the List Template Gallery (BaseTemplate 114). Quick, but tied to the site's features and language, and not suitable for repeatable deployment.

2. Feature-based list definition (farm solution). A <ListTemplate> plus your own schema.xml, deployed in a WSP. This was the standard approach in 2007 and 2010. It works only on-premises, and custom list definitions make upgrades and migrations harder, so avoid it for new work.

3. Content types + provisioning (recommended). Create the library from the standard Document Library template (101), and add your site columns and content types with a provisioning script. The library stays "standard", so upgrades and migrations stay simple. PnP provisioning templates make this repeatable:

# Capture from a reference site
Get-PnPSiteTemplate -Out .\ContractsLibrary.xml -Handlers Fields, ContentTypes, Lists
# Apply to a new site
Invoke-PnPSiteTemplate -Path .\ContractsLibrary.xml

4. SharePoint Online site scripts and list templates. In Microsoft 365, site scripts (createSPList action) and custom list templates (Add-SPOListDesign) let users create your library from the "New" menu, with your columns and views already in place.

Explore content types with PowerShell

SharePoint Server:

$web = Get-SPWeb https://sharepoint.ravindran.in/sites/HR
$web.ContentTypes |
    Select-Object Name, @{n='Id';e={$_.Id.ToString()}}, @{n='Parent';e={$_.Parent.Name}}, Group, Hidden |
    Sort-Object Id | Format-Table -AutoSize
$web.Dispose()

Which content types a library uses:

$web  = Get-SPWeb https://sharepoint.ravindran.in/sites/HR
$list = $web.Lists["Documents"]
$list.ContentTypes | Select-Object Name, @{n='Id';e={$_.Id.ToString()}}
"BaseTemplate: $($list.BaseTemplate)  BaseType: $($list.BaseType)"
$web.Dispose()

SharePoint Online (PnP.PowerShell):

Connect-PnPOnline -Url https://sharepointonline.ravindran.in/sites/HR -ClientId $env:PNP_CLIENT_ID -Interactive
Get-PnPContentType | Select-Object Name, @{n='Id';e={$_.Id.StringValue}}, Group | Sort-Object Id
Get-PnPContentType -List "Documents"
